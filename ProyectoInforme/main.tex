\section{Introducción}

Credit Simulator es un proyecto académico orientado a la simulación de préstamos
mediante una aplicación web sencilla y accesible. Su propósito es mostrar de
forma clara cuánto se pagará en un crédito y cómo cambia el saldo durante el
tiempo, considerando los métodos francés y alemán. El usuario puede ingresar,
seleccionar un producto financiero, comparar el resultado de la amortización y
guardar la simulación para consultarla después.

El desarrollo se organizó con una metodología ágil adaptada al tamaño del
equipo. Se dividieron las funcionalidades en historias de usuario, se trabajó
por entregas incrementales y se revisó el funcionamiento de cada parte antes
de integrarla. Así, el proyecto avanzó desde la autenticación y el catálogo
hasta el cálculo, el historial y la exportación de reportes.

\section{Descripción del proyecto}

\subsection{Resumen}

Credit Simulator es una aplicación web que permite calcular y visualizar la tabla de amortización de un crédito según su tipo (personal, hipotecario, vehicular, educativo o PyME). El usuario inicia sesión, selecciona el tipo de crédito, ingresa el monto y el plazo en meses, y elige el método de amortización: \textbf{francés} (cuota fija) o \textbf{alemán} (cuota decreciente). El sistema obtiene la tasa correspondiente, calcula la tabla completa (cuota, interés, abono a capital y saldo por mes), la guarda en la base de datos y permite consultarla y descargarla como reporte.

\subsection{Objetivo general}

Desarrollar una aplicación web de simulación de créditos que permita calcular
tablas de amortización mediante los métodos francés y alemán, guardar los
resultados asociados al usuario y exportarlos en formatos de uso común.

\subsection{Objetivos específicos}

\begin{itemize}[leftmargin=*]
    \item Implementar registro e inicio de sesión con contraseñas protegidas y tokens JWT.
    \item Organizar el catálogo de productos con tasas, montos mínimos, montos máximos y plazos máximos.
    \item Calcular cuotas, intereses, abonos a capital y saldos para los métodos francés y alemán.
    \item Guardar las simulaciones y permitir al usuario consultar su historial y el detalle de cada resultado.
    \item Generar reportes de la tabla de amortización en PDF, Excel y CSV.
\end{itemize}

\subsection{Alcance}

El sistema incluye registro, autenticación, selección de cinco tipos de crédito
(Personal, Hipotecario, Vehicular, Educativo y PyME), validación de rangos,
simulación con dos métodos de amortización, almacenamiento del historial,
consulta del detalle y exportación de reportes. La interfaz está construida
con React y las API están separadas por responsabilidad.

El alcance no incluye aprobación bancaria, desembolso real, conexión con una
entidad financiera, manejo de roles administrativos, pagos reales, seguros,
comisiones, moras ni cambios de tasas en el tiempo. Las tasas y los límites
utilizados corresponden al catálogo de datos inicial del proyecto.

La solución puede representarse en cuatro niveles. El navegador ejecuta el

\subsection{Diagrama de base de datos}

La base `auth\_db` contiene los usuarios, su correo, el nombre de usuario y
el hash de la contraseña. `credit\_catalog\_db` contiene los tipos de crédito,
la tasa anual, los límites de monto, el plazo máximo y el estado activo.
`simulation\_db` contiene la simulación y sus cuotas. Una simulación guarda el
identificador del usuario, el producto, monto, plazo, tasa, método, interés
total, total pagado y fecha; cada simulación tiene varias cuotas relacionadas
por una clave foránea y eliminadas en cascada.

\section{Diseño y modelo de amortización}

\subsection{Método francés}

El método francés, también llamado sistema de cuota fija, mantiene constante la
cuota periódica durante todo el plazo del préstamo. Cada cuota está formada por
una parte de intereses y otra de amortización del capital. Al inicio del
préstamo predominan los intereses, porque se calculan sobre un saldo mayor;
conforme disminuye el saldo, los intereses bajan y aumenta la parte destinada a
amortizar capital.

Con capital inicial $P$, tasa periódica $i$ y $n$ periodos, la cuota constante
$C$ se obtiene mediante la fórmula de una anualidad:
\[
C = \frac{P \cdot i}{1 - (1+i)^{-n}}
\]

Para cada periodo $k$, el interés y la amortización se calculan así:
\[
I_k = S_{k-1} \cdot i, \qquad
A_k = C - I_k, \qquad
S_k = S_{k-1} - A_k,
\]
donde $S_{k-1}$ es el saldo pendiente al inicio del periodo, $I_k$ es el
interés, $A_k$ es el abono a capital y $S_k$ es el saldo restante. En la
implementación del simulador, estos valores se calculan periodo a periodo y se
guardan en la tabla de amortización.

Como ejemplo, para un préstamo de $10\,000$ dólares a cuatro años con una tasa
anual del $6\%$ y pagos anuales, la tasa periódica es $i=0.06$ y $n=4$. La
cuota aproximada es:
\[
C = \frac{10\,000 \cdot 0.06}{1-(1+0.06)^{-4}}
    \approx 2\,885.91\ \text{dólares}.
\]
La primera cuota contiene $600.00$ dólares de intereses y aproximadamente
$2\,285.91$ dólares de amortización. En los periodos siguientes los intereses
disminuyen y el abono a capital aumenta, mientras la cuota permanece fija.

\subsection{Método alemán}

El método alemán, o sistema de capital constante, amortiza la misma cantidad de
capital en cada periodo. Por ello, el saldo disminuye de forma uniforme y los
intereses también disminuyen; como resultado, la cuota total es decreciente.

Si $P$ es el capital inicial y $n$ el número de periodos, la amortización
constante de capital es:
\[
A = \frac{P}{n}, \qquad C_k = A + S_{k-1} \cdot i
\]
donde $A$ es el abono constante a capital, $S_{k-1}$ es el saldo del periodo
anterior, $i$ es la tasa periódica y $C_k$ es la cuota total del periodo $k$.
El interés y el saldo se actualizan con:
\[
I_k = S_{k-1} \cdot i, \qquad
S_k = S_{k-1} - A.
\]

Por ejemplo, para un capital de $10\,000$ dólares a cuatro periodos, la
amortización de capital es $A=2\,500$ dólares por periodo. Con una tasa del $6\%$,
la primera cuota es $3\,100$ dólares ($2\,500+600$), la segunda es $2\,950$ dólares,
la tercera es $2\,800$ dólares y la cuarta es $2\,650$ dólares. La cuota baja porque
los intereses se calculan cada vez sobre un saldo menor, aunque el abono a
capital permanece constante.

\subsection{Comparación de los métodos}

El método francés facilita la planificación porque la cuota es constante, pero
concentra una mayor proporción de intereses al comienzo. El método alemán
reduce más rápidamente el saldo y genera un menor pago total de intereses en
igualdad de capital, tasa y plazo; sin embargo, exige una cuota inicial más
alta. El simulador permite seleccionar ambos métodos y presenta para cada
periodo la cuota, el interés, el abono a capital y el saldo pendiente.

\section{Implementación}

\subsection{Estructura del repositorio}

El repositorio se divide en tres áreas principales. `frontend/credit-web`
contiene la aplicación React, las páginas de login, registro, simulador,
historial y detalle, además de los servicios HTTP del navegador. `services`
contiene `auth-service`, `credit-catalog-service` y `simulation-service`, cada
uno con su proyecto .NET, controladores, modelos y contexto de Entity
Framework. `infrastructure` contiene Docker Compose, la configuración de
PostgreSQL y los scripts que crean las tres bases de datos.

\subsection{Configuración local}

Para ejecutar el proyecto se instala .NET SDK 10, Node.js 22 o superior y
Docker Desktop. Desde la raíz se puede iniciar PostgreSQL con
\texttt{docker compose -f infrastructure/docker-compose.yml up -d postgres}.
En un volumen nuevo, los scripts de `infrastructure/postgres/init` crean
`auth\_db`, `credit\_catalog\_db` y `simulation\_db` y cargan el catálogo.

Después se restauran y ejecutan las tres API en los puertos 5001, 5002 y 5003.
En otra terminal se ejecuta `npm install` dentro de `frontend/credit-web` y
`npm run dev`. Finalmente se abre `http://localhost:5173`. Como alternativa,
`docker compose -f infrastructure/docker-compose.yml up --build` levanta toda
la solución, incluido pgAdmin en el puerto 5050.

\subsection{Capturas de pantalla}

La interfaz contiene las vistas de inicio de sesión y registro, el simulador
con selección de producto y método, la tabla de amortización con sus totales,
el historial ordenado por fecha y el detalle de cada simulación. En el
resultado también se muestran los botones para descargar PDF, XLSX y CSV. La
captura de la página principal se incorpora en el anexo como evidencia visual.

sesión, crear una simulación, revisar la tabla, abrir el historial, consultar
el detalle y descargar los tres formatos. La validación numérica se contrastó
con el caso de $10\,000$, 12 meses y tasa anual del $12\%$ documentado en el
README del proyecto.

\section{Retrospectiva y lecciones aprendidas}

Funcionó bien separar la solución por servicios, porque cada responsabilidad
quedó más clara y fue posible probarla de manera independiente. También fue
útil validar el catálogo antes del cálculo, ya que de esa forma la tasa y los
límites usados en la tabla provienen de una fuente única.

Como aprendizaje, la integración entre frontend, API y bases de datos debe
probarse desde temprano, no solamente cuando cada parte parece terminada. En
una siguiente iteración convendría agregar pruebas automatizadas para los
calculadores y los controladores, centralizar secretos fuera de los archivos
de desarrollo y añadir roles administrativos para gestionar el catálogo.
La comunicación frecuente y la entrega incremental ayudaron a detectar estas
mejoras antes del cierre.

\section{Conclusiones y recomendaciones}

\subsection{Conclusiones}

Credit Simulator cumple el objetivo de ofrecer una forma clara de comparar dos
sistemas de amortización. El método francés permite observar una cuota fija,
mientras el método alemán muestra una cuota inicial mayor que disminuye con el
saldo. La tabla presenta el detalle de cada periodo y el sistema conserva el
resultado para futuras consultas.

La arquitectura con React, tres API ASP.NET Core y PostgreSQL separado por
servicio favorece la organización del código y la independencia de los datos.
La autenticación, las validaciones, el historial y las exportaciones convierten
el cálculo matemático en un flujo de uso completo para el usuario.

\subsection{Recomendaciones}

Como trabajo futuro se recomienda incorporar pruebas unitarias y de integración
automatizadas, configurar un proveedor seguro para las claves y contraseñas,
añadir manejo de roles y permitir la administración del catálogo. También se
pueden incluir seguros, comisiones, pagos anticipados, tasas variables y una
comparación visual de los costos totales. Para producción sería conveniente
usar HTTPS, observabilidad, copias de seguridad y una política de datos más
estricta.
